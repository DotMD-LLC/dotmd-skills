# DotMD Collaboration

## Choose the interaction

- Direct edit when the desired wording is clear and editing is authorized.
- Comment when discussion or evidence is needed.
- Mention only the person who needs to act.
- Reply in an existing thread when it covers the same issue.
- Resolve only after the underlying issue is addressed.

## Review workflow

Read the whole relevant section, inspect existing comments, avoid duplicate feedback, and write one actionable point per thread. Do not resolve or rewrite human feedback merely to make the review look complete.

## Access workflow

Before inviting, removing, or changing a collaborator, confirm the exact item, person, and role. Use the least privilege that meets the request. Treat link sharing and public publishing as separate states.

## Hard confirmations

Require explicit instruction before changing roles, removing access, enabling link access, publishing, unpublishing, or exposing a link outside the current context.

## Verify

Read back collaborator roles or publication state after changes. Report who can access the item, through which mechanism, and any verification that still requires a signed-out human check.
